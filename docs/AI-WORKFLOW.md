# AI 效率与审美工作流（2.16）

## 按任务读取

`djian_context` 按 text / layout / motion / audio / all 返回字段。默认使用用户当前选中对象，其次使用当前播放头；没有有效用户状态时看 0 秒。也可明确指定 `ids`、`time`、`start/end`；`wholeProject:true` 查看全项目。

返回包含关联分组、双向跟随/遮罩/连接关系、共享元素、相关素材元数据、轨道锁、元素设计锁和项目审美简报。默认最多 30 个实体，可调到 100。文本、数组及深层对象有长度限制，返回截断说明；嵌套合成只返回入口，不展开内部时间线。需要编辑截断字段时先读 `djian_timeline{detail:"full"}`，不能把摘要写回完整字段。

`djian_apply_ops` 的常驻说明与参数结构精简；完整合同仍由引擎维护。`djian_operation{names:["updateOverlay"]}` 按需取参数合同及相关用法，最多 5 个操作。字节对比见 [基准记录](benchmarks/ai-workflow.json)：单个 apply 工具定义由 30,422 字节降至 1,777 字节；加入 context/operation/rehearse 三个工具后合计约 5,545 字节。此为 UTF-8 序列化大小，不是实测 token 数或模型响应速度。

## 一批修改先预演

1. 用 `djian_context` 读取当前范围及 rev。
2. `djian_rehearse{action:"preview",ops:[…],ids:[…],label:"…"}` 在独立时间线副本执行和校验，返回每条回执、范围违规、实际修改字段、抽样计划、规则问题、前后联络图。
3. 默认工具图像为修改后；`action:"show",id,view:"before"` 看修改前。界面 **制作工具 → 设计与审片 → AI 修改预演** 可并排查看。
4. 检查结果后 `action:"apply",id` 采用，或在界面点“采用预演”。支持撤销，重复采用不会再写一次。

拒绝操作、无效时间线、超出指定范围或渲染失败均不能采用。局部范围不允许修改项目级配置。新增元素保留预演生成的 ID；采用的是已经验证的结果。采用时再次校验时间线版本、素材文件大小/修改时间及审美规范；任何变化需要重新预演。

预演不写时间线。`render:false` 可只验证结构和规则，明确返回未生成画面，不冒充视觉通过；采用前应按任务需要补充看图。预演最多 200 条操作、12 个采样时间（默认 6），缓存最多 16 个方案，30 分钟过期，重启失效。相同版本/素材/规范/参数的重复预演复用结果。

## 按影响检查

- 文字与几何修改：受影响对象的显示区间取样，实测浏览器文字边界。
- 动画与时长修改：在受影响区间取多个时刻；主轨剪辑时长变化会纳入后续被移动的片段。
- 音量/音频修改：不渲染画面，明确标记 audio 模式；响度仍使用交付质量工具单独实测。
- 分组、绑定关系和共享元素扩展影响范围；全局规范或全局排序保守扩大范围。
- 抽样发现的同画面邻近文字冲突也会报告。返回实际取样时间、候选数量及截断状态，不能解释成逐帧检查。

实际图像仍复用现有渲染缓存；此版没有宣称跨任意时间线版本复用不变图层。复杂依赖、动态遮挡、蒙版以及字体审美仍需看图核对。

## 项目审美简报

**制作工具 → 设计与审片 → 项目审美简报** 可编辑受众、发布平台、情绪、信息密度、视觉重点、字体层级、动效与停留规则。与既有风格卡共同保存到项目元数据，加入任务上下文和新轮次风格提示。不会自动更改画面。

AI 也可用 `djian_style set` 保存上述字段。保留既有配色/字号/安全边距/动效数量规则，预演会检查部分可量化偏离（如字号相差超过 25%、同场景动效预设数量）。这些是规则提示，不是审美评分；焦点、留白、情绪仍由看图和用户选择判断。明确的新要求优先，不能把一次临时选择记作永久喜好。

验证入口：`npm test`、`npm run test:ai-workflow`、`npm run test:ai-ui`、`npm run test:visual`。

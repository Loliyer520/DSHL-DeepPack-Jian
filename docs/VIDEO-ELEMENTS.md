# 视频元素与内嵌视频播放

视频现在可以作为 `overlays` 中的原生元素，与文字、图片和图形混排。旧工程的视频轨道继续可用，不需要手动转换。

## 使用

上传视频后，在素材库右键选择「作为视频元素插入」，或者打开「插入 → 视频」。选中后可设置源入点、倍速、音量、静音、定格、适应方式和圆角；位置、尺寸、排序、分组、动画和遮罩使用同一套元素工具。

默认静音，开启原声需要关闭「静音」。视频元素的声音单独映射到时间线，避免运动模糊采样和嵌套渲染重复播放原声。音量关键帧使用元素 `animations.volume`。切分推进右半段源入点，定格保持原入点；复制保留参数。

```json
{
  "op": "addOverlay",
  "id": "demo-video",
  "kind": "video",
  "video": {
    "src": "demo.mp4",
    "inPoint": 0.5,
    "speed": 1,
    "muted": true,
    "volume": 1,
    "fit": "contain",
    "radius": 16
  },
  "startSeconds": 0,
  "endSeconds": 3,
  "x": 0.5,
  "y": 0.5,
  "w": 0.7,
  "h": 0.6
}
```

AI 用 `updateOverlay.patch.video` 更新局部参数，`arrangeOverlay` 或插入索引调整层级。后面的普通元素可以覆盖视频，字幕仍按既有规则在最上层。视频可使用形状／文字等作为遮罩源；当前不支持把视频本身当作另一元素的 Alpha／亮度遮罩源。

## 播放和导出

- 导出和服务端取帧改用 Remotion OffthreadVideo 请求对应源帧，不依赖浏览器视频标签恰好完成 seek。覆盖视频轨道、画中画和视频元素。
- 内嵌合成预览复用原生视频解码器，沿根播放状态与累计倍速播放；暂停或跳转时定位，避免 Freeze 下每帧重新 seek。若新的定位在上一轮 seek 中到达，上一轮完成后会定位最新目标。
- 视频元素临近开始时预挂载。含视频的元素／组合预览采用单时间样本，避免同时开启多个运动模糊解码器；正式导出保留配置的运动模糊。
- 导出默认并发最多 4 个渲染页面，避免高核数机器同时打开过多视频解码器；调用方仍可明确指定 `concurrency`。
- 视频元素加入素材引用、AI 任务上下文、预合成、便携工程、重链接、代理和导出预检。源入点与播放范围超出已知素材时长会被预检报告。

## 大视频预览

在「制作工具 → 工程与缓存」生成 720p 代理。已生成的代理默认用于预览，用户可以关闭；正式导出仍读原素材。新版代理使用 H.264/YUV420p、faststart 和 30 帧关键帧间隔，减少跳转解码距离。原有代理参数指纹已升级，需重新生成新版代理。

代理生成仍由用户启动，不会自动转码全部原始素材。原始编码、分辨率、硬盘和嵌套层数会影响性能；不支持的源编码应先转换。累计嵌套速度超出浏览器连续播放范围时，预览改为逐帧定位；导出按时间取帧。

时间线格式为 v22，内部包为 0.4.0，旧工程自动迁移。

验证入口：`npm run test:video-elements`（带 B 帧测试视频、随机取帧、入点/倍速/定格、嵌套、导出后像素与音频、图文遮挡）、`npm run test:video-preview`（真实浏览器连续播放、快速定位、插入与保存）。
